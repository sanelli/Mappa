# Mappa Attributes
The [Mappa](https://www.nuget.org/packages/Mappa/) package contains all the attributes that can be used to drive the behaviour of the [Mappa source generator](https://www.nuget.org/packages/Mappa.Generator/).

This is the list of attributes provided:
- `Mappa`: Identifies partial classes that are meant to be source generated by the [Mappa source generator](https://www.nuget.org/packages/Mappa.Generator/);
- `MappaDependencyInjection`: Identifies a partial registrar class for which the generator emits a method that registers `[Mappa]` mapper types into an `IServiceCollection` (same assembly by default; optionally additional assemblies via `InjectFromAssemblies` — see [MappaDependencyInjection](#mappadependencyinjection));
- `MappaIgnore`: Identifies methods that should not be used for mapping;
- `MappaProjection`: Opt-in/opt-out for `IQueryable<TSource>` → `IQueryable<TTarget>` deferred projection on a mapper class or map method (see [MappaProjection](#mappaprojection));
- `MappaDependency`: Identifies a property or field inside a mapper class that can be used when identifying suitable mappings between two types; fields and properties tagged on **accessible base classes of the mapper** are also considered; methods on the dependency type **and its base classes** are considered when the field or property type is that type or a derived type;
- `MappaStaticDependency`: Defines a static class whose methods can be used as dependencies while performing mappings;
- `MappaSettings`: Allows specifying mapping behaviour (for example, culture when parsing or formatting date/time, `Guid`, and numeric types, and format when converting numeric types to `string`);
- `MappaUseProperty`: When mapping structured types (`class`, `struct`, and records) allows specifying which source property to use for a target property or constructor parameter; `TargetPropertyName` and `SourcePropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaIgnoreTargetProperty`: When mapping structured types via an empty constructor, excludes a target property from property-initializer mapping; has no effect when mapping uses a constructor with parameters; `TargetPropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaMustMapTargetProperty`: When mapping structured types via an empty constructor (or empty-constructor-like factory), requires that listed non-required target properties—or all of them when no names are provided—are mapped; otherwise generation fails with **MP00065** (see [MappaMustMapTargetProperty](#mappamustmaptargetproperty));
- `MappaAllowInaccessibleSourceMembers`: Opt-in to read private/protected source properties via generated `UnsafeAccessor` methods (see [MappaAllowInaccessibleSourceMembers](#mappaallowinaccessiblesourcemembers));
- `MappaAllowInaccessibleTargetMembers`: Opt-in to write private/protected target properties and/or invoke inaccessible target constructors via generated `UnsafeAccessor` methods (see [MappaAllowInaccessibleTargetMembers](#mappaallowinaccessibletargetmembers));
- `MappaAssignFromContext`: When mapping structured types, allows specifying which value from a `MappaContext` to use for a target property or constructor parameter; `TargetPropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaAssignToContext`: When mapping structured types via the constructor-map strategy, stores the value of a target property or field in `MappaContext` after the target object has been fully constructed; `TargetPropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaInvokeMethodAttribute`: When mapping structured types via the constructor-map strategy, forces a target property or constructor parameter to be mapped by invoking a named method; supports an optional `SourcePropertyName` named parameter (see [MappaInvokeMethodAttribute](#mappainvokemethodattribute)); `TargetPropertyName` and optional `SourcePropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaAssignFromConstant`: When mapping structured types, allows specifying a constant value for a target property or constructor parameter; `TargetPropertyName` may be a single name or a [dot-separated nested property path](#nested-property-paths);
- `MappaNullSubstitute`: When mapping structured types, substitutes a null source member with a constant (`AssignValue`) or a method call (`InvokeMethod`) before mapping continues; optional `SourcePropertyName`; supports [nested property paths](#nested-property-paths) (see [MappaNullSubstitute](#mappanullsubstitute));
- `MappaBeforeMap`: Invokes a named hook immediately before the generated root mapping body (see [MappaBeforeMap and MappaAfterMap](#mappabeforemap-and-mappaaftermap));
- `MappaAfterMap`: Invokes a named hook immediately after the generated root mapping body and before returning the target (see [MappaBeforeMap and MappaAfterMap](#mappabeforemap-and-mappaaftermap));
- `MappaTransformer`: Marks a method as a value transformer (`T` → `T`) that is applied at every matching mapping site of the mapper class — to the source value before it is mapped and to the mapped value before it is assigned or returned (see [MappaTransformer and MappaApplyTransformer](#mappatransformer-and-mappaapplytransformer));
- `MappaApplyTransformer`: Applies a named transformer to the annotated map method, optionally limited to one source member or nested path; the transformer may live on the mapper, on a `static` class type, or on a mapper field/property (see [MappaTransformer and MappaApplyTransformer](#mappatransformer-and-mappaapplytransformer));
- `MappaObjectFactory`: Forces construction of a target type via a named factory method instead of `new` (see [MappaObjectFactory](#mappaobjectfactory));
- `MappaUseConstructor`: Forces empty or parameterized constructor selection for the map method return type or a nested target type (see [MappaUseConstructor](#mappauseconstructor)); also available as `MappaUseConstructorAttribute<T1>` … `<T1, …, T8>` for exact signatures;
- `MappaTypeMapping`: When mapping structured types or interfaces, allows defining the target type depending on the source type; also available as `MappaTypeMapping<TTarget, TSource>`;
- `MappaTypeMappingDefault`: Describes the default behaviour for polymorphic methods defined via `MappaTypeMapping`; also available as `MappaTypeMappingDefault<TDefault>` for `MapSourceType` with an explicit target type.
- `MappaProtobufPolymorphismSetup`: Identifies the protobuf `oneof` case property (`{Oneof}Case`) that drives protobuf polymorphism on a map method; single-property form for proto→POCO and POCO→proto, `(target, source)` form for proto→proto (see [Protobuf oneof polymorphism](#protobuf-oneof-polymorphism));
- `MappaProtobufTypeMapping`: Defines one arm of a protobuf `oneof` polymorphism mapping; three constructors for proto→POCO, POCO→proto and proto→proto (no generic form);
- `MappaProtobufTypeMappingDefault`: Describes the default behaviour of protobuf `oneof` polymorphism (`Throw`, `NoMap`, `MapTo`).
- `MappaMapEnumMember`: Configures explicit enum↔integral, enum↔string, or enum↔enum member pairings (see [MappaMapEnumMember, MappaMapEnumIgnore, and MappaMapEnumDefault](#mappamapenummember-mappamapenumignore-and-mappamapenumdefault));
- `MappaMapEnumIgnore`: Excludes a specific enum member from mapping;
- `MappaMapEnumDefault`: Configures fallback behaviour when an enum value cannot be mapped;
- `MappaSourcePreferredInterfaceImplementation`: When a source type implements multiple closed versions of the same collection/dictionary interface family, forces which closed interface to use (method-only; see [Preferred interface implementations](#preferred-interface-implementations)); also available as `MappaSourcePreferredInterfaceImplementation<TImplementingType, TClosedInterface>`;
- `MappaTargetPreferredInterfaceImplementation`: Same preference for concrete multi-interface **target** types (method-only; see [Preferred interface implementations](#preferred-interface-implementations)); also available as `MappaTargetPreferredInterfaceImplementation<TImplementingType, TClosedInterface>`;

The [Mappa](https://www.nuget.org/packages/Mappa/) package also provides the `MappaContext` class that can be used to pass contextual values to mappers via the `MappaAssignFromContext` attribute, store mapped values via the `MappaAssignToContext` attribute, supply context to methods invoked via the `MappaInvokeMethodAttribute` attribute, supply context to before/after map hooks, or supply context to object factory methods. When `ReferenceReusing` or `MaxRuntimeDepth` is enabled, `MappaContext` also owns a private `MappaReferenceManager` used by generated code (via `UnsafeAccessor`) to track mapped references (keyed by source identity and `typeof(TTarget)`) and nesting depth. `MappaContext` is not thread-safe: use one instance per logical mapping operation and do not share a single instance across concurrent mappings without external synchronization.

## MappaDependencyInjection

`[MappaDependencyInjection]` marks a **registrar** partial class (not a mapper). The generator emits a method that registers `[Mappa]` mapper types into `Microsoft.Extensions.DependencyInjection.IServiceCollection`. By default only mappers in the **registrar's assembly** are discovered. When `InjectFromAssemblies` is non-empty, mappers from each marker type's assembly are included as well (**additive**). Marker types are not specially registered unless they also have `[Mappa]` and pass the usual filters.

### Requirements and conflicts

- The registrar class must be `partial`. Non-partial classes with `[MappaDependencyInjection]` are filtered out by the incremental syntax provider (no registration method and no **MP00070** from the normal pipeline). **MP00070** remains as a defensive diagnostic if a non-partial registrar is supplied directly to the DI algorithm.
- Applying both `[Mappa]` and `[MappaDependencyInjection]` on the same class is an error (**MP00071**). Keep `[Mappa]` on mapper classes and `[MappaDependencyInjection]` on a separate registrar.
- The consuming project must reference `Microsoft.Extensions.DependencyInjection` (or Abstractions plus an implementation that provides `IServiceCollection` extension methods such as `AddSingleton`).

### Generated method name

Resolved in order:

1. A non-empty `MethodName` property value;
2. Otherwise the constructor argument (`ConstructorMethodName`);
3. Otherwise `Register{ClassName}`.

When the registrar is `static` and `ExtensionMethod` is `true` (default), the generated method is an extension method on `IServiceCollection`. When `ExtensionMethod` is `false`, or the registrar is not `static`, a normal instance/static method taking `IServiceCollection` is emitted.

### Properties

| Property | Default | Description |
|----------|---------|-------------|
| `ExtensionMethod` | `true` | When the registrar is `static`, emit an extension method. Ignored for non-static registrars. |
| `MethodName` | *(unset)* | Overrides the generated method name. |
| `Accessibility` | `Public` | Accessibility of the generated method (`Public`, `Private`, `Protected`, `Internal`, `ProtectedInternal`). Prefer non-static registrars for `Protected` / `ProtectedInternal`. |
| `ServiceLifetime` | `Singleton` | Lifetime used for registrations (`Singleton`, `Scoped`, `Transient` → `AddSingleton` / `AddScoped` / `AddTransient`). |
| `InjectInterfaces` | `ClassOnly` | How concrete types and interfaces are registered (see below). |
| `IgnoreType` | `[]` | Types to exclude: concrete mappers are not registered; when interface injection is enabled, listed interfaces are also excluded from interface registrations. |
| `InjectFromAssemblies` | `[]` | Marker types whose **assemblies** are scanned for additional `[Mappa]` mappers (in addition to the registrar's assembly). Markers are assembly identifiers only; they are not registered unless they themselves have `[Mappa]` and pass filters. |

### InjectInterfaces

- **`ClassOnly`** (default): register each mapper as `AddX<Mapper>()`.
- **`InterfaceOnly`**: for each mapper, register every eligible interface as `AddX<IInterface, Mapper>()`. Interfaces from `IgnoreType` are omitted. If a mapper has no remaining eligible interfaces, **MP00072** is reported and that mapper is skipped.
- **`InterfaceAndClass`**: register the concrete type, then each eligible interface with a factory that resolves the shared concrete instance via `GetRequiredService<Mapper>()`. Same **MP00072** behaviour when no eligible interfaces remain.

Eligible interfaces are all interfaces implemented by the mapper (`AllInterfaces`), ordered by display name.

### Discovery rules

- Always scan the current compilation assembly for `[Mappa]` types.
- When `InjectFromAssemblies` is non-empty, also scan each distinct marker type's containing assembly (deduplicated). Assemblies are ordered by identity display name for stable output.
- Existing filters (`IgnoreType`, static skip / **MP00073**, `InjectInterfaces` / **MP00072**) apply across every scanned assembly.
- The registrar type itself is never registered.
- Static `[Mappa]` classes cannot be DI type arguments; they report **MP00073** and are skipped.
- Nested `[Mappa]` types in scanned assemblies are included.
- Referenced assemblies are **not** scanned unless listed via an `InjectFromAssemblies` marker (or they are the registrar's own assembly).

Hint name for the generated file: `{FullTypeName}.DependencyInjection.g.cs`.

See also: [tutorial](./tutorial.md#mappadependencyinjection-attribute), [algorithm](./mappa-generator-algorithm.md#dependency-injection-registration), [error codes](./error-codes.md) (**MP00070**–**MP00073**), [MappaDependencyInjectionRegistrar.cs](../Mappa.Samples/MappaDependencyInjectionRegistrar.cs) (with `InjectFromAssemblies`), and [MappaDependencyInjectionSameAssemblyRegistrar.cs](../Mappa.Samples/MappaDependencyInjectionSameAssemblyRegistrar.cs).

## MappaProjection

`[MappaProjection]` controls whether map methods with an `IQueryable<TSource>` → `IQueryable<TTarget>` signature are handled as deferred queryable projections. Projection remains signature-driven when the attribute is absent.

Apply the attribute to a mapper class or to an individual map method:

- `Enabled = BooleanSetting.Enable` (default when the attribute is present): treat eligible `IQueryable` map methods as projections;
- `Enabled = BooleanSetting.Disable`: skip the projection strategy for the annotated method (or for projection-signature methods on the annotated class); the generator falls through to the normal container / eager mapping path (warning **MP00061** may apply);
- `Enabled = BooleanSetting.Undefined`: ignore this attribute application and use the parent scope or the signature-driven default.

Method-level values override class-level values. `[MappaProjection]` does not replace `[MappaIgnore]`, which excludes a method from generation entirely.

See also: [tutorial — IQueryable projection](./tutorial.md#iqueryable-projection) and [IQueryableProjectionMapper.cs](../Mappa.Samples/IQueryableProjectionMapper.cs).

## MappaDependency and MappaStaticDependency

`MappaDependency` marks a field or property on the mapper (or an accessible base class) whose type provides mapping methods. When Mappa needs to map from a source type to a target type, it searches for a suitable method on:
- the mapper class and its base classes;
- dependency fields or properties marked with `[MappaDependency]`, including methods declared on the dependency type and its base classes;
- static classes marked with `[MappaStaticDependency]`.

When the root map method is `static`, instance dependencies are not available unless the dependency field or property is also `static`.

## Nested property paths

Attributes that accept `TargetPropertyName` and/or `SourcePropertyName` support **dot-separated nested property paths** (for example `"Address.City"` or `"Location.Address.City"`) in addition to flat single-segment names. Path segments name properties by default; when `MapSourceFields` / `MapTargetFields` are enabled, segments may also name instance fields.

| Attribute | Target path | Source path |
|-----------|-------------|-------------|
| `MappaUseProperty` | yes | yes |
| `MappaInvokeMethod` | yes | optional `SourcePropertyName` |
| `MappaAssignFromConstant` | yes | — |
| `MappaNullSubstitute` | yes | optional `SourcePropertyName` |
| `MappaAssignFromContext` | yes | — |
| `MappaAssignToContext` | yes | — |
| `MappaIgnoreTargetProperty` | yes | — |

**Target paths**

- A single segment (`"City"`) keeps the existing flat behaviour.
- A multi-segment path (`"Address.City"`) applies when mapping the **first** segment (`Address`). Remaining segments are resolved while mapping the nested type.
- A missing first or later target segment reports warning **MP00033**.

**Source paths**

- May be longer than the target path, but must not be shorter (segment count). A shorter source path reports error **MP00043**.
- Every source segment must exist on the resolved source type. A missing segment reports error **MP00044**.
- At the leaf target member, the generator emits a chained source read from the current nested source receiver (reusing intermediate temps when present).
- Conditional access (`?.` vs `.`) is chosen from the **receiver** type at each step: with `#nullable disable`, reference types and `Nullable<T>` use `?.`; with `#nullable enable`, only annotated nullable references and `Nullable<T>` use `?.`; otherwise `.` is used.
- The chain appends `?? throw new System.NullReferenceException("...")` (with the original attribute source path) only when the access expression can be null (any `?.` was used, or the leaf type is nullable-capable) **and** the target member cannot be null. Plain non-nullable value-type leaves (for example `int`) never get `?? throw`.

**Combining attributes under the same root**

- Nested `[MappaIgnoreTargetProperty]` under a shared root with `[MappaUseProperty]` (or other nested attributes) is honoured: ignored sibling members are omitted from the nested object initializer.

See also: [Mappa generator algorithm — nested property paths](./mappa-generator-algorithm.md#nested-property-paths), [tutorial](./tutorial.md#nested-property-paths), and [NestedPropertyPathAttributeMapper.cs](../Mappa.Samples/NestedPropertyPathAttributeMapper.cs).

## MappaUseProperty

When mapping structured types, Mappa pairs source and target members by name. `[MappaUseProperty]` overrides that pairing by specifying which source property supplies the value for a given target property or constructor parameter. Both `TargetPropertyName` and `SourcePropertyName` support [nested property paths](#nested-property-paths).

## MappaIgnoreTargetProperty

When mapping via an empty constructor, Mappa assigns each target property with an accessible setter from the corresponding source property. `[MappaIgnoreTargetProperty]` excludes a target property from this mapping. It has no effect when the target is constructed via a constructor with parameters. `TargetPropertyName` supports [nested property paths](#nested-property-paths). A nested ignore under the same root as a nested `[MappaUseProperty]` (for example ignore `Address.ZipCode` while mapping `Address.City`) is applied to that sibling member.

## MappaMustMapTargetProperty

When mapping via an empty constructor (or an empty-constructor-like object factory), unmapped non-required target properties normally produce warning **MP00017** and are skipped. `[MappaMustMapTargetProperty]` elevates selected (or all) of those properties to a hard requirement:

- `[MappaMustMapTargetProperty]` with no property names: every non-required mappable target property must be mapped;
- `[MappaMustMapTargetProperty("PropertyA", "PropertyB")]`: only the listed non-required properties must be mapped; other unmapped non-required properties still produce **MP00017**.

If a required must-map property cannot be mapped, the generator reports error **MP00065** and does not generate a usable mapping. Listing a property that is already `required` reports warning **MP00066** and continues. Listing a name that does not exist on the target reports warning **MP00033** and continues. Combining the same property name with `[MappaIgnoreTargetProperty]` reports error **MP00007**. Property names are flat (single-segment) only; nested paths are not supported.

See also: [MappaMustMapTargetPropertyAttributeMapper.cs](../Mappa.Samples/MappaMustMapTargetPropertyAttributeMapper.cs).

## MappaAllowInaccessibleSourceMembers

By default Mappa only reads **accessible** source properties (and accessible source fields when `MapSourceFields` is enabled). `[MappaAllowInaccessibleSourceMembers]` on a map method opts in to reading private or protected source properties — and, when `MapSourceFields` is enabled, private or protected source fields — through generated [`UnsafeAccessor`](https://learn.microsoft.com/dotnet/api/system.runtime.compilerservices.unsafeaccessorattribute) helpers:

- `[MappaAllowInaccessibleSourceMembers]`: every eligible inaccessible source property (and field when field mapping is enabled) may be read;
- `[MappaAllowInaccessibleSourceMembers("Name", "Id")]`: only the listed flat property or field names may be read when inaccessible.

Set-only source properties remain ignored. Member names are flat (single-segment) only; nested paths are not supported. Unknown names report warning **MP00033**. The compilation must provide `UnsafeAccessorAttribute` (typically .NET 8+) and C# 12+; otherwise the generator reports error **MP00067**. Queryable projection map methods cannot use this attribute (**MP00069**).

Explicitly implemented interface properties are **not** mapped through this attribute. Use `MappaSettings.MapSourceExplicitInterfaceProperties` instead (interface cast, never `UnsafeAccessor`).

See also: [InaccessibleMembersMapper.cs](../Mappa.Samples/InaccessibleMembersMapper.cs).

## MappaAllowInaccessibleTargetMembers

By default Mappa only writes **accessible** target setters (and accessible target fields when `MapTargetFields` is enabled) and only invokes **accessible** constructors. `[MappaAllowInaccessibleTargetMembers]` on a map method opts in to inaccessible target members via generated `UnsafeAccessor` helpers:

- `[MappaAllowInaccessibleTargetMembers]`: every eligible inaccessible target property (and field when field mapping is enabled) may be written and inaccessible constructors may be invoked (subject to the flags below);
- `[MappaAllowInaccessibleTargetMembers("Name", "Age")]`: only the listed flat property or field names may be written when inaccessible; constructor access is independent of the name list.

Named parameters:

- `AllowProperties` (default `true`): whether inaccessible target properties may be written;
- `AllowFields` (default `true`): whether inaccessible target fields may be written when `MapTargetFields` is enabled;
- `AllowConstructors` (default `true`): whether inaccessible target constructors (parameterless or parameterized) may be invoked.

Setting `AllowProperties`, `AllowFields`, and `AllowConstructors` all to `false` reports error **MP00068**. Get-only non-collection target properties remain unmappable; get-only collection / dictionary / queue / stack properties continue to use the existing post-construction fill rules when their getters can be accessed (including via UnsafeAccessor when opted in). Member names are flat only; unknown names report **MP00033**. Requires `UnsafeAccessor` / C# 12+ (**MP00067**). Not allowed on queryable projection methods (**MP00069**).

When inaccessible setters, inaccessible field writes, or unsafe-accessor constructors are used, assignments that would normally appear in an object initializer are emitted **after** construction. Generated helpers live in a file-local `__MappaInaccessibleAccessors` type in the same namespace as the mapper.

Explicitly implemented interface properties are **not** mapped through this attribute. Use `MappaSettings.MapTargetExplicitInterfaceProperties` instead (interface cast after construction, never `UnsafeAccessor`).

See also: [InaccessibleMembersMapper.cs](../Mappa.Samples/InaccessibleMembersMapper.cs).

## MappaNullSubstitute

`[MappaNullSubstitute]` substitutes a **null source member** before mapping continues to the target. The substitute is typed as the **source** member type `T`; conversion to the target runs afterward. Because substitution yields non-null `T`, mapping `T?` → non-nullable `T` is allowed for that member.

Exactly one mode must be set:

- **`AssignValue`**: emit `source ?? constant` (or the equivalent null check under `#nullable disable`).
- **`InvokeMethod`**: invoke a method only when the source is null; when non-null, use the source as-is. The method accepts `T?`/`T` and returns non-null `T`. Optional `InvokeMethodType` (static method on that type) or `InvokeMethodSource` (instance method on a mapper field/property). Do not set both locators. `InvokeMethod` is **not** supported on `IQueryable` projections (**MP00119**).

`TargetPropertyName` and optional `SourcePropertyName` support [nested property paths](#nested-property-paths). Distinct from `[MappaAssignFromConstant]`, which writes the target directly and skips mapping; when both target the same member, AssignFromConstant wins and **MP00118** is reported.

Diagnostics: **MP00115** (mode missing/ambiguous), **MP00116** (both locators), **MP00117** (duplicate attributes), **MP00118** (ignored for AssignFromConstant), **MP00119** (InvokeMethod on projection).

See also: [MappaNullSubstituteMapper.cs](../Mappa.Samples/MappaNullSubstituteMapper.cs).

## ReplaceNullWithEmptyContainer

`MappaSettings.ReplaceNullWithEmptyContainer` (default off) maps a null source collection or dictionary to an empty target container instead of producing `null` or throwing. Enable at class or method level, or via `mappa.replacenullwithemptycontainer` in `.editorconfig`.

Supported empties include concrete types with a parameterless constructor (`new List<T>()`), allow-listed interfaces/arrays (`[]`), and well-known immutable/frozen/readonly wrappers (`.Empty` or equivalent). Span/Memory family types and `IProducerConsumerCollection<T>` are excluded. The same empty forms apply inside `IQueryable` projections when the setting is on.

See also: [ReplaceNullWithEmptyContainerMapper.cs](../Mappa.Samples/ReplaceNullWithEmptyContainerMapper.cs).

## MappaAssignFromConstant

`[MappaAssignFromConstant]` assigns a compile-time constant value to a target property or constructor parameter. The constant must be compatible with the target member type. `TargetPropertyName` supports [nested property paths](#nested-property-paths).

## MappaAssignFromContext

`[MappaAssignFromContext]` reads a value from `MappaContext` and assigns it to a target property or constructor parameter. The map method must accept `MappaContext` as its second parameter. `TargetPropertyName` supports [nested property paths](#nested-property-paths).

## MappaAssignToContext

`[MappaAssignToContext]` stores the mapped value of a target property or field into `MappaContext` after the target object has been fully constructed. The map method must accept `MappaContext` as its second parameter. Each context key must be unique within a method. `TargetPropertyName` supports [nested property paths](#nested-property-paths). For a nested path such as `"Address.City"`, the generator still maps the parent `Address` as part of building the result, then writes the leaf from the constructed object (for example `context[key] = result.Address.City`).

## MappaInvokeMethodAttribute

When the constructor-map strategy is used, this attribute forces the source generator to map a target property or constructor parameter by invoking a named method. It does not apply when mapping nested inner types. `TargetPropertyName` and optional `SourcePropertyName` support [nested property paths](#nested-property-paths).

### Method location

Depending on which constructor overload is used, the invoked method is resolved as follows:

- `(targetPropertyName, methodName)`: a `static` or instance method declared on the mapper class or an accessible base class. When the root map method is `static`, only `static` methods are considered; otherwise both `static` and instance methods are considered.
- `(targetPropertyName, classType, methodName)`: a `static` method declared on the specified type or one of its base classes.
- `(targetPropertyName, fieldName, methodName)`: an instance method declared on the type of the field or property (including its base classes). The field or property must be declared on the mapper class or an accessible base class. When the root map method is `static`, the field or property must also be `static`.

When multiple methods with the same name exist in a type hierarchy, methods declared on the most derived type are preferred.

### SourcePropertyName

`SourcePropertyName` is an optional named parameter on any constructor overload. When set, it selects which source property is passed to method overloads that accept a source-property argument for the target member specified by `TargetPropertyName`. It overrides the default name-based source property match for that invoke-method mapping. Like `TargetPropertyName`, it may be a single name or a [dot-separated nested property path](#nested-property-paths).

Example:

```csharp
[MappaInvokeMethod(
    nameof(Target.PropertyA),
    nameof(CustomMap),
    SourcePropertyName = nameof(Source.SourceProperty))]
public partial Target Map(Source input);
```

When only the invoke-method mapping needs a custom source property, prefer `SourcePropertyName` on `[MappaInvokeMethod]` instead of combining it with `[MappaUseProperty]`. Use `[MappaUseProperty]` when other target members on the same map method also require a non-default source property mapping. If both `[MappaUseProperty]` and `SourcePropertyName` target the same member, the generator emits warning **MP00031** because `[MappaUseProperty]` is ignored for that invoke-method mapping.

### Candidate requirements

Every candidate method must satisfy all of the following:

- Its name matches the method name specified in the attribute exactly.
- Its return type is equal to the target property or constructor parameter type, or is implicitly convertible to it.
- It is accessible from the mapper class.
- It satisfies the `static` or instance requirement described above for the attribute overload in use.

### MappaContext

When the root map method accepts a `MappaContext` as its second parameter, invoked methods may also accept a `MappaContext` parameter. The `MappaContext` parameter is always the last parameter when combined with source and/or source-property arguments, and its type must be `Mappa.MappaContext`. Overloads that require `MappaContext` are ignored when the map method does not provide one. If only `MappaContext`-requiring overloads exist and the map method has no `MappaContext` parameter, mapping fails.

### Overload selection priority

If multiple candidate methods match at the same selection tier, the generator reports error **MP00042** instead of picking one arbitrarily. When candidates remain in the same tier after hierarchy tie-breaking (a method declared on a more derived type wins over one on a base type), the first matching overload in the following list is selected. Tiers that reference a source property apply only when a source property is available for the target member (via name matching, `[MappaUseProperty]`, or `SourcePropertyName` on `[MappaInvokeMethod]`):

1. Three parameters: source type (exact), source property (exact), `MappaContext` — requires the map method to provide `MappaContext`.
2. Two parameters: source type (exact), source property (exact).
3. Three parameters: source type (exact or implicitly convertible), source property (exact or implicitly convertible), `MappaContext` — requires the map method to provide `MappaContext`.
4. Two parameters: source type (exact or implicitly convertible), source property (exact or implicitly convertible).
5. Two parameters: source type (exact), `MappaContext` — requires the map method to provide `MappaContext`.
6. One parameter of the same type as the source type.
7. Two parameters: source type (exact or implicitly convertible), `MappaContext` — requires the map method to provide `MappaContext`.
8. One parameter with a type implicitly convertible from the source type.
9. Two parameters: source property (exact), `MappaContext` — requires the map method to provide `MappaContext`.
10. One parameter of the same type as the source property.
11. Two parameters: source property (exact or implicitly convertible), `MappaContext` — requires the map method to provide `MappaContext`.
12. One parameter with a type implicitly convertible from the source property type.
13. One parameter of type `MappaContext` — requires the map method to provide `MappaContext`.
14. No parameters.

## MappaBeforeMap and MappaAfterMap

`[MappaBeforeMap]` and `[MappaAfterMap]` invoke named hooks around the generated body of a **root** mapping method. They do not apply to nested type mappings (collection elements, dictionary keys/values, tuple items, constructor parameters, or property initializers). Both attributes may be applied to the mapper class and/or to individual mapping methods, and both allow multiple instances.

### Hook location

Depending on which constructor overload is used, the hook is resolved as follows:

- `(methodName)`: a `static` or instance method declared on the mapper class or an accessible base class. When the root map method is `static`, only `static` hooks are considered; otherwise both `static` and instance hooks are considered.
- `(classType, methodName)`: a `static` method declared on the specified type or one of its base classes. Instance methods on an explicit type are not valid.
- `(fieldName, methodName)`: a method declared on the type of the field or property identified by `fieldName` (including base classes and interface members when the declared type is an interface). Instance hooks are invoked through the field or property. Static hooks are invoked through the member's declared type without evaluating the field or property. When the root map method is `static`, an instance hook requires a `static` field or property.

When multiple methods with the same name exist in a type hierarchy, methods declared on the most derived type are preferred.

### Supported signatures

A hook must return `void`. Valid signatures are:

| Phase | Signatures (priority order) |
|-------|-----------------------------|
| Before map | `Hook(ref TSource, MappaContext)`, `Hook(ref TSource)`, `Hook(MappaContext)`, `Hook()` |
| After map | `Hook(ref TTarget, MappaContext)`, `Hook(ref TTarget)`, `Hook(MappaContext)`, `Hook()` |

Because `ref` is invariant, the `ref` parameter type must match the mapping source type (before) or target type (after) exactly. Context-aware signatures are considered only when the root map method provides a `MappaContext` parameter. Within a winning tier, the same most-derived / unique-candidate rules used by `[MappaInvokeMethod]` apply; an ambiguous winning tier reports error **MP00042**.

### Ordering and duplicates

- **Before map**: class-level hooks run before method-level hooks. Declaration order is preserved within each scope.
- **After map**: method-level hooks run before class-level hooks. Declaration order is preserved within each scope.
- Class-level hooks resolve independently for each mapping method based on that method's source and target types.
- If class and method scope resolve to the same hook for the same phase, the generator reports warning **MP00046** and invokes the hook once (at the class-level position for before map, and at the method-level position for after map).
- If a hook cannot be resolved with a supported signature, the generator reports warning **MP00045**, skips that hook, and still generates the core mapping.

See also: [tutorial](./tutorial.md#mappabeforemap-and-mappaaftermap-attributes), [algorithm](./mappa-generator-algorithm.md#before-and-after-map-hooks), and [MappaBeforeAfterMapHooksAttributeMapper.cs](../Mappa.Samples/MappaBeforeAfterMapHooksAttributeMapper.cs).

## MappaTransformer and MappaApplyTransformer

Value transformers rewrite a value of type `T` into another value of the same type `T` (for example trimming or upper-casing a `string`) while a mapping is being generated.

- `[MappaTransformer]` marks a method of the mapper class (or of an accessible base class) as a transformer for **every** map method of the mapper.
- `[MappaApplyTransformer]` is placed on a single map method, may be repeated, and selects a transformer by name. The selected method does not need `[MappaTransformer]`.

Transformers run at every mapping site whose type matches exactly (including nullability): the root source and root return value, and also nested sites such as property initializers, constructor parameters, collection elements, dictionary keys/values, and tuple items. At each site the source value is transformed before it is mapped and the mapped value is transformed before it is assigned or returned.

### Transformer location

`[MappaApplyTransformer]` resolves the method as follows:

- `(methodName)`: a `static` or instance method declared on the mapper class or an accessible base class. When the map method is `static`, only `static` transformers are considered.
- `(classType, methodName)`: a `static` method declared on `classType` or one of its base classes.
- `(sourcePropertyName, methodName)` and `(sourcePropertyName, classType, methodName)`: same lookup as above, but the transformer only runs when the source member identified by `sourcePropertyName` (a single name or a [dot-separated nested path](#nested-property-paths)) is mapped. A name that does not exist on the map source type reports error **MP00112**.
- `FieldName` (named property, not a constructor argument): the method is resolved on the declared type of a mapper field or property and invoked through it (instance methods) or through its declared type (`static` methods). Using `ClassType` together with `FieldName` reports warning **MP00113** and skips that attribute instance.

An unresolved or inaccessible method reports warning **MP00111** and the attribute is skipped; the core mapping is still generated.

### Supported signatures

| Parameters | Notes |
|------------|-------|
| `T Transform(T value)` | Always considered. |
| `T Transform(in T value)` | `in` is allowed on the value parameter. |
| `T Transform(T value, MappaContext context)` | Considered only when the map method has a `MappaContext` parameter. |
| `T Transform(in T value, MappaContext context)` | Same as above. |

The return type must equal the parameter type, nullability included (`string` and `string?` are different sites). `ref`/`out` parameters, by-reference returns and `async` methods are not allowed. Open generic transformers are allowed when `T` can be bound exactly to the site type and the constraints are satisfied. A `[MappaTransformer]` method with an invalid signature reports warning **MP00110** and is ignored. Transformers may be `static` or instance methods with any accessibility, as long as they are accessible from the mapper. Because same-type `T` → `T` transformers also look like map methods, mark them with `[MappaIgnore]` when you do not want them to be discovered as mapping methods.

### Ordering

When several transformers match the same site, they all run, in this order (declaration order is kept inside each tier):

1. `[MappaApplyTransformer]` attributes, in attribute order;
2. `[MappaTransformer]` methods declared on the mapper class;
3. `[MappaTransformer]` methods of base classes, most derived type first;
4. `[MappaTransformer]` methods of dependencies, only when `MappaTransformerFromDependency` is enabled (see below).

The same transformer is never applied twice to the same value on the same side. When a map method calls another method generated by Mappa for the same type, the callee already applies the class-level transformers, so they are not applied again around the call.

### Dependencies

`[MappaTransformer]` methods declared on types registered with `[MappaDependency]` (fields/properties) or `[MappaStaticDependency]` are **ignored by default**. Set `MappaTransformerFromDependency = BooleanSetting.Enable` in `[MappaSettings]` on the mapper class or on a map method to include them (a method-level value overrides the class-level one; `mappa.transformerfromdependency` can set the global default). A dependency that only exposes transformers does not provide any map method, so it reports **MP00016**; suppress it with `#pragma warning disable MP00016` and an explanatory comment, as done in the sample.

### Projections

Value transformers are never emitted inside `IQueryable` projection generation. `[MappaApplyTransformer]` on a projection map method is an error (**MP00114**). Unlike before/after map hooks, class-level `[MappaTransformer]` methods alone do **not** invalidate a projection method: they are simply not applied.

See also: [tutorial](./tutorial.md#mappatransformer-and-mappaapplytransformer-attributes), [algorithm](./mappa-generator-algorithm.md#value-transformers), and [MappaValueTransformerMapper.cs](../Mappa.Samples/MappaValueTransformerMapper.cs).

## MappaObjectFactory

`[MappaObjectFactory]` forces Mappa to create a target instance by invoking a named factory method instead of calling a constructor with `new`. The attribute may be applied to the mapper class and/or to individual mapping methods, and allows multiple instances. Class-scope and method-scope registrations are unioned for each map method.

Each registration identifies the **target type** that should be produced by the factory. When mapping that target type (including nested property or constructor-parameter mappings whose exact target type matches), the generator prefers the factory over mapping constructors, empty constructors, and parameterized constructors. Factories are not used for `IQueryable` projection element construction; combining a projection map with an object factory for the element target reports error **MP00064**.

### Factory location

Depending on which constructor overload is used, the factory is resolved as follows (same location rules as `[MappaInvokeMethod]` / before/after hooks):

- `(targetType, methodName)`: a `static` or instance method declared on the mapper class or an accessible base class. When the root map method is `static`, only `static` factories are considered.
- `(targetType, classType, methodName)`: a `static` method declared on the specified type or one of its base classes.
- `(targetType, fieldName, methodName)`: a method declared on the type of the field or property identified by `fieldName`. Instance factories are invoked through the field or property; static factories are invoked through the member's declared type.

When multiple methods with the same name exist in a type hierarchy, methods declared on the most derived type are preferred.

### Supported signatures

The factory must return a type assignable to the registered target type. Signature tiers are tried in this order:

| Tier | Signature | Behaviour |
|------|-----------|-----------|
| 1 | `(TSource, MappaContext)` | Fully produced — factory return value is used as-is (no property assignment) |
| 2 | `(TSource)` | Fully produced — factory return value is used as-is |
| 3 | `(MappaContext)` | Empty-constructor-like — matching settable properties are filled from the source after the call |
| 4 | `()` | Empty-constructor-like — matching settable properties are filled from the source after the call |
| 5 | Other parameters | Parameterized-constructor-like — each parameter is mapped from source properties like a non-empty constructor |

Context-aware signatures (tiers 1 and 3) are considered only when the map method (or nested mapping context) provides a `MappaContext`. Within a winning tier, the same most-derived / unique-candidate rules used by `[MappaInvokeMethod]` apply; an ambiguous winning tier reports error **MP00042**.

### Duplicates and unresolved factories

- If more than one factory is registered for the same target type after unioning class and method attributes, the generator reports error **MP00062**.
- If a factory cannot be resolved to an accessible method with a supported signature, the generator reports warning **MP00063** and falls back to the normal constructor strategies.

See also: [tutorial](./tutorial.md#mappaobjectfactory-attribute), [algorithm](./mappa-generator-algorithm.md#10-constructor-strategy), and [MappaObjectFactoryMapper.cs](../Mappa.Samples/MappaObjectFactoryMapper.cs).

## MappaUseConstructor

`[MappaUseConstructor]` forces the generator to construct a target type (the map method return type, or a nested type when `typeof(T)` / `targetType` is supplied) using a specific constructor kind or exact signature. Apply it to mapping methods only (`AllowMultiple = true`). Object factories still win when registered for the same type; an unused attribute warns with **MP00092**.

### Forms

| Form | Meaning |
|------|---------|
| `[MappaUseConstructor(ConstructorType.NoParameters)]` | Force the empty-constructor path for the map method return type (suppresses mapping-constructor auto-selection for that type). |
| `[MappaUseConstructor(ConstructorType.WithParameters, typeof(T1), …)]` | Force the exact parameterized signature `(T1, …)` for the return type. |
| `[MappaUseConstructor(typeof(TTarget), ConstructorType.NoParameters)]` | Same as empty, but for nested (or otherwise explicit) `TTarget`. |
| `[MappaUseConstructor(typeof(TTarget), ConstructorType.WithParameters, typeof(T1), …)]` | Exact signature for nested/explicit `TTarget`. |
| `[MappaUseConstructor<T1, …, T8>]` / `[MappaUseConstructor<T1, …>(typeof(TTarget))]` | Generic shorthand for `WithParameters` with those parameter types (optional `targetType`). |

`ConstructorType.WithParameters` without parameter types is invalid (**MP00089**). `NoParameters` must not list parameter types (**MP00089**). Missing empty or matching parameterized constructors report **MP00087** / **MP00088**. A selected constructor that cannot be mapped reports **MP00090**. Duplicate attributes for the same effective target type report **MP00091**.

See also: [tutorial](./tutorial.md#mappauseconstructor-attribute), [algorithm](./mappa-generator-algorithm.md#10-constructor-strategy), and [MappaUseConstructorMapper.cs](../Mappa.Samples/MappaUseConstructorMapper.cs).

`MappaSettings` can be applied to the mapper class or to individual map methods. Method-level settings override class-level settings, which in turn override `.editorconfig` values.

The following settings are available:

- `DateTimeOffsetFormat`: the format to use when mapping `string`s to and from `System.DateTimeOffset`;

- `DateTimeOffsetStyle`: the [DateTimeStyles](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.datetimestyles) to use when parsing `string`s to `System.DateTimeOffset` (unset values inherit; does not affect `ToString`);
- `DateOnlyStyle`: the [DateTimeStyles](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.datetimestyles) to use when parsing `string`s to `System.DateOnly` (unset values inherit; does not affect `ToString`);

- `TimeSpanFormat`: the format to use when mapping `string`s to and from `System.TimeSpan`;
- `GuidFormat`: the format to use when mapping `string`s to and from `System.Guid`;
- `ByteFormat`, `SByteFormat`, `ShortFormat`, `UShortFormat`, `IntFormat`, `UIntFormat`, `LongFormat`, `ULongFormat`, `DecimalFormat`, `FloatFormat`, `DoubleFormat`: the format to use when converting the corresponding numeric type to `string` (numeric formats apply to `ToString` only);

- `GlobalNumberStyle`: the default [NumberStyles](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.numberstyles) for parsing `string`s to numeric types when the corresponding type-specific style is unset (unset values inherit; type-specific style properties override this global default when both are set; does not affect `ToString`);
- `CultureInfoSetting`: defines which culture to use when mapping any of the above types and numeric types (current culture, invariant culture, or user-defined culture);
- `CultureName`: defines the culture to use when user-defined culture is selected by `CultureInfoSetting`;
- `ProtobufOptional`: enables or disables the ability of the [Mappa source generator](https://www.nuget.org/packages/Mappa.Generator/) to handle `optional` fields in protobuf models;
- `BsonWellKnownTypes`: when `Enable`, maps `MongoDB.Bson` well-known types (`ObjectId` ↔ `string`/`byte[]`, `Decimal128` → `decimal`) without a separate dependency package (disabled by default; requires a reference to [MongoDB.Bson](https://www.nuget.org/packages/MongoDB.Bson/));
- `ProtobufWellKnownTypes`: when `Enable`, maps `Google.Protobuf.WellKnownTypes` (`Timestamp`, `Duration`, and scalar wrappers) without a separate dependency package (disabled by default; requires a reference to [Google.Protobuf](https://www.nuget.org/packages/Google.Protobuf/));
- `OneOfWellKnownTypes`: when `Enable`, maps [OneOf](https://www.nuget.org/packages/OneOf/) / `OneOfBase` shapes (including Option `OneOf<T, None>`) without a separate Mappa dependency package (disabled by default; requires a reference to [OneOf](https://www.nuget.org/packages/OneOf/)). Exact-arm `T → OneOf<…, T, …>` via identity/implicit conversion remains available regardless of this setting;
- `PragmaWarning`: allows surrounding the generated methods with a `#pragma warning disable` block;
- `FastCollections`: uses `Span<T>` to make mappings involving arrays and `System.Collections.Generic.List<T>` faster;
- `ReplaceNullWithEmptyContainer`: when enabled, a null source collection or dictionary is mapped to an empty target container instead of producing `null` or throwing (disabled by default; see [ReplaceNullWithEmptyContainer](#replacenullwithemptycontainer));
- `ContainerCapacityConstructors`: supports mapping custom containers using (if available) a constructor accepting an integer value representing the initial capacity of the container;
- `PreventEnumerableCount`: when enabled, avoids calling `Enumerable.Count` when mapping from a source that does not expose `Count` or `Length` to a fixed-size target such as `T[]`, `Span<T>`, `ReadOnlySpan<T>`, `Memory<T>`, or `ReadOnlyMemory<T>`; a growable `List<T>` buffer is used so the source is enumerated only once;
- `EnumerableConcreteType`: selects whether mappings to sequence-like collection interfaces (for example `IEnumerable<T>`, `IList<T>`, `ICollection<T>`, `IReadOnlyList<T>`, `IReadOnlyCollection<T>`) use `List<T>` (default) or `T[]` as the concrete buffer; concrete `List<T>` targets are unchanged;
- `DictionaryAssignment`: selects whether dictionary-to-dictionary mappings insert entries with the indexer (`target[key] = value`, default) or `IDictionary<TKey, TValue>.Add(key, value)`; applies to dictionary return types and get-only dictionary properties;
- `PolymorphicMapMethodWithMatchingDefaultAttribute`: when enabled, `MappaTypeMappingDefault` can be used to locate an appropriate polymorphic method when looking for the mapping between two types;
- `CompatibleMapMethod`: when enabled, nested existing-method reuse may invoke a map method whose parameter is a base type or interface of the required source and whose return type is a derived type of the required target (disabled by default);
- `MappaTransformerFromDependency`: when enabled, `[MappaTransformer]` methods declared on `[MappaDependency]` / `[MappaStaticDependency]` types are applied as value transformers (disabled by default). See [MappaTransformer and MappaApplyTransformer](#mappatransformer-and-mappaapplytransformer);
- `CaseInsensitivePropertyMap`: when enabled, source property (and, when field mapping is enabled, field) names are matched case-insensitively when pairing a target member or constructor parameter with a source member by name;
- `IgnoreUnderscoreForPropertyMap`: when enabled, underscore characters are stripped from names before comparing a target member or constructor parameter with a source member by name;
- `MapSourceFields`: when enabled, accessible instance fields on the source type may be read when pairing with a target property, field, or constructor parameter by name (including nested paths and attribute-driven member names). Disabled by default (`Undefined`). Compiler-generated backing fields and `static` / `const` / `ref` / `fixed` fields are never included. Private or protected source fields additionally require `[MappaAllowInaccessibleSourceMembers]`. When both a property and a field remain eligible for the same name, the **property wins**;
- `MapTargetFields`: when enabled, accessible instance fields on the target type may be written or initialized when pairing with a source property or field by name (including nested paths, post-constructor assignment, and attribute-driven member names). Disabled by default. Compiler-generated backing fields, `static` / `const` / `ref` / `fixed`, and `readonly` fields are never assigned. Private or protected target fields additionally require `[MappaAllowInaccessibleTargetMembers]` (subject to `AllowFields`). When both a property and a field remain eligible for the same name, the **property wins**;
- `MapSourceExplicitInterfaceProperties`: when enabled, source properties that are explicitly implemented interface members may be read via a cast to the declaring interface (disabled by default). Explicit interface properties use this setting and an interface cast — not `[MappaAllowInaccessibleSourceMembers]` / `UnsafeAccessor`;
- `MapTargetExplicitInterfaceProperties`: when enabled, target properties that are explicitly implemented interface members may be written via a cast to the declaring interface after construction (never in an object initializer). When a parameterized constructor is selected, remaining explicit-interface target properties are also assigned after construction. Explicit interface properties use this setting and an interface cast — not `[MappaAllowInaccessibleTargetMembers]` / `UnsafeAccessor`;
- `CaseInsensitiveEnumMap`: when enabled, enum member names or `Description` attribute values are matched case-insensitively when mapping between enums or from `string` to an enum;
- `EnumStringMapSetting`: selects whether enum-to-string and string-to-enum mappings match members by name (default) or by `Description` attribute value;
- `EnumToEnumMapSetting`: selects whether enum-to-enum mappings match members by name (default), by underlying numeric value, or by `Description` attribute value.
- `IdentityMapDeepCopy`: selects how same-type identity mappings copy reference-type and struct roots — return the original reference (`ShallowCopy`, default), clone via `MemberwiseClone` without recursively copying nested references (`DeepCopy`), or clone and recursively map instance fields (`NestedDeepCopy`). Primitives, enums, and `string` always assign and ignore this setting.
- `ProjectionEnumStringMapSetting`: overrides `EnumStringMapSetting` for enum↔string mappings inside `IQueryable` projections (falls back to `EnumStringMapSetting` when unset);
- `ProjectionEnumToEnumMapSetting`: overrides `EnumToEnumMapSetting` for enum↔enum mappings inside `IQueryable` projections (falls back to `EnumToEnumMapSetting` when unset);
- `ProjectionCaseInsensitiveEnumMap`: overrides `CaseInsensitiveEnumMap` for enum mappings inside `IQueryable` projections (falls back to `CaseInsensitiveEnumMap` when unset);
- `ProjectionGuidFormat`: overrides `GuidFormat` for `Guid`↔`string` mappings inside `IQueryable` projections (falls back to `GuidFormat` when unset);
- `ProjectionCultureInfoSetting`: overrides `CultureInfoSetting` for string parse/format inside `IQueryable` projections (falls back to `CultureInfoSetting` when unset);
- `ProjectionCultureName`: overrides `CultureName` when `ProjectionCultureInfoSetting` is user-defined (falls back to `CultureName` when unset);
- `ReferenceReusing`: when enabled, already-mapped reference-type instances are reused when the same source instance appears again in the object graph (cycles and shared DAGs). Reuse is per **declared target type** (`typeof(TTarget)` together with source identity). Requires a `MappaContext` parameter on the map method. Disabled by default.
- `MaxRuntimeDepth`: maximum nesting depth allowed while executing a mapping (`short`). Use `-1` (`MappaSettingsAttribute.UndefinedDepth`) or any negative value to inherit the parent setting. When fully unset, the effective default is `0` (unlimited). A positive value limits nested reference-type mapping depth (`1` means root plus one nested level). Requires a `MappaContext` parameter. Exceeding the limit at runtime throws `MappaException`.
- `MaxCompileTimeDepth`: maximum nesting depth allowed while the source generator discovers mapping strategies (`short`). Generator-only (not emitted into generated code). Use `-1` / negative to inherit. When fully unset, the effective default is `50`. An effective value of `0` disables compile-time depth tracking. Exceeding the limit reports error **MP00076**.
- `BreakCompileTimeCycles`: when enabled, re-entering the same source/target type pair during strategy discovery synthesizes a **private** map method for that pair (instead of reporting **MP00077**) and invokes it at the cycle edge. Reports warning **MP00078**. Generator-only; disabled by default. Pair with `ReferenceReusing` when the object graph also cycles at runtime.

When resolving parse styles for a mapping target, the generator uses the type-specific style when set; otherwise it falls back to the global style for that family (`GlobalDateTimeStyle` or `GlobalNumberStyle`). If neither is set, the existing parse overload without a style parameter is emitted unchanged.

## MappaTypeMapping and MappaTypeMappingDefault

`MappaTypeMapping` defines how a polymorphic source type maps to a concrete target type. Multiple attributes can be applied to the same method, one per source type.

Use either the non-generic form or the generic helper (equivalent behaviour):

- `[MappaTypeMapping(typeof(TTarget), typeof(TSource))]`
- `[MappaTypeMapping<TTarget, TSource>]`

`MappaTypeMappingDefault` defines the behaviour when the runtime source type does not match any `[MappaTypeMapping]` entry:
- `Undefined`: this setting should never be used;
- `Throw`: throws `ArgumentOutOfRangeException` or the exception defined in the attribute;
- `Default`: returns `default`;
- `Null`: returns `null`;
- `MapSourceType`: maps the source type to the target type of the method or the type specified in the attribute;
- `InvokeMethod`: invokes a method in the mapper with the name specified in the attribute to perform the mapping; the attribute can also specify the type on which the method is defined—in that case the method must be `static`. The method can optionally accept a `MappaContext` parameter. When more than one method matches, the generator reports error **MP00042** (see [Overload selection priority](#overload-selection-priority) for `[MappaInvokeMethod]` tier rules).

For `MapSourceType` with an explicit target type, the following forms are equivalent:

- `[MappaTypeMappingDefault(MappaTypeMappingDefaultBehavior.MapSourceType, typeof(TDefault))]`
- `[MappaTypeMappingDefault<TDefault>]`

## Protobuf oneof polymorphism

Protobuf `oneof` fields are exposed by `protoc` as a `{Oneof}Case` property (for example `ResultCase`), a nested `{Oneof}OneofCase` enum (`ResultOneofCase`, whose first member is `None`) and one property per arm. Mappa can dispatch on that case (or on the CLR runtime type when the source is a POCO) with three method-only attributes. Only **message-typed** arms are supported; scalar arms are rejected.

| Attribute | Purpose |
|-----------|---------|
| `[MappaProtobufPolymorphismSetup]` | **Required**, exactly one per method. Names the oneof case property. |
| `[MappaProtobufTypeMapping]` | One per arm (`AllowMultiple`). |
| `[MappaProtobufTypeMappingDefault]` | Optional. Behaviour when no arm matches. |

All constructors use the **(target, source)** order, like `[MappaTypeMapping]`.

| Direction | Setup | Arm |
|-----------|-------|-----|
| proto → POCO | `[MappaProtobufPolymorphismSetup("ResultCase")]` (source case property) | `[MappaProtobufTypeMapping(typeof(TTargetPoco), "Ok")]` (target type, source case name) |
| POCO → proto | `[MappaProtobufPolymorphismSetup("ResultCase")]` (target case property) | `[MappaProtobufTypeMapping("Ok", typeof(TSourcePoco))]` (target case name, source type) |
| proto → proto | `[MappaProtobufPolymorphismSetup("TargetCase", "SourceCase")]` | `[MappaProtobufTypeMapping("TargetOk", "SourceOk")]` (target case name, source case name) |

How the mapping is generated:

- **proto source**: `switch` on the source `{Oneof}Case`; each arm reads the arm property (a message), maps it, and produces the target. The source case `None` and any unlisted case follow the default behaviour.
- **POCO source**: `switch` on the runtime type of the source (type patterns), one `case` per arm.
- **proto target**: an empty target message is created and the selected oneof property is assigned inside the arm; other (non-oneof) fields of the target message are not mapped by this strategy.
- The arm message/POCO types are mapped with the regular strategies (including existing map methods), so no extra map method is needed.
- Exactly one `[MappaProtobufPolymorphismSetup]` is required; a setup without arms is allowed and generates only the default branch.
- Like `[MappaTypeMapping]`, the strategy runs only at the root of the map method (or immediately after nullable unwrapping). The protobuf attributes cannot be mixed with `[MappaTypeMapping]` / `[MappaTypeMappingDefault]` on the same method (**MP00093**).
- The case `None` cannot be used as an explicit arm (**MP00100**); an arm cannot be repeated (**MP00102**).

`MappaProtobufTypeMappingDefaultBehavior` (via `[MappaProtobufTypeMappingDefault]`):

- `Undefined`: this setting should never be used (**MP00105**);
- `Throw`: throws `ArgumentOutOfRangeException` or the exception type given in the attribute (must derive from `Exception`, **MP00021**). This is also the behaviour when the attribute is missing;
- `NoMap`: leaves the target oneof unset (`None`). Only valid when the target is a protobuf message (**MP00103** otherwise); an exception type argument is ignored with warning **MP00106**;
- `MapTo`: maps the unmatched source (including source case `None`) into the message of a named target arm and assigns that arm: `[MappaProtobufTypeMappingDefault(MappaProtobufTypeMappingDefaultBehavior.MapTo, "Fallback")]`. Only valid when the target is a protobuf message (**MP00103**), and the case name is required (**MP00104**).

```csharp
[Mappa]
public sealed partial class Mapper
{
    // proto -> POCO
    [MappaProtobufPolymorphismSetup("ResultCase")]
    [MappaProtobufTypeMapping(typeof(OkModel), "Ok")]
    [MappaProtobufTypeMapping(typeof(ErrorModel), "Error")]
    public partial ResultModel Map(ResultMessage source);

    // POCO -> proto
    [MappaProtobufPolymorphismSetup("ReplyCase")]
    [MappaProtobufTypeMapping("Ok", typeof(OkModel))]
```

## Preferred interface implementations

When a concrete type implements **multiple closed versions** of the same open collection or dictionary interface family (for example both `IEnumerable<int>` and `IEnumerable<string>`), Mappa selects which closed interface drives element / key / value typing and codegen access (`foreach` casts, `Add`, indexer).

### Attributes

Both attributes are **method-only**, allow multiple instances, and take two type arguments:

| Attribute | Side |
|-----------|------|
| `[MappaSourcePreferredInterfaceImplementation(typeof(TImplementing), typeof(TClosedInterface))]` | Source |
| `[MappaTargetPreferredInterfaceImplementation(typeof(TImplementing), typeof(TClosedInterface))]` | Target |

Generic forms `MappaSourcePreferredInterfaceImplementation<TImplementing, TClosedInterface>` and `MappaTargetPreferredInterfaceImplementation<TImplementing, TClosedInterface>` are equivalent.

- **`TImplementing`** must be a concrete implementing type (not an open generic interface family).
- **`TClosedInterface`** must be a closed generic interface that `TImplementing` actually implements (exact match), and must belong to a recognized collection/dictionary family (`IEnumerable<T>`, `ICollection<T>`, `IDictionary<TKey,TValue>`, and related families).

Matching is by **implementing type + open interface family + side**. At most one attribute per key is allowed on a map method (**MP00083**).

### Selection order

For each side and family, Mappa resolves in this order:

1. A matching preference attribute whose closed interface is **usable** for the current mapping (nested element/key/value strategies exist);
2. Otherwise the unique usable **implicit** implementation;
3. Otherwise the unique usable **explicit** implementation;
4. Otherwise fall through (legacy first-match helpers are not used for type-argument extraction).

Usability is probed recursively with a recursion guard so dual-interface graphs cannot loop forever.

### Source vs target

- Prefer **source** attributes when the multi-interface type is enumerated or read (element / key / value extraction, `foreach` casts).
- Prefer **target** attributes when the multi-interface type is written (`Add` / indexer) and more than one closed interface could accept mapped elements.

Use the family that strategy detection actually consults. Collection element mapping resolves the **`IEnumerable<T>`** family; dictionary mapping resolves `IDictionary` / `IReadOnlyDictionary` / `IEnumerable<KeyValuePair<,>>` as applicable. Preferring `ICollection<string>` does not match an `IEnumerable`-family resolution.

### Diagnostics

| Code | When |
|------|------|
| **MP00079** | Matching attribute interface cannot be used for the mapping |
| **MP00080** | First argument is not a concrete implementing type |
| **MP00081** | Implementing type does not implement the preferred closed interface |
| **MP00082** | Attribute was never needed (unique usable candidate already exists, or the type never appears) |
| **MP00083** | Duplicate attribute for the same implementing type, family, and side |
| **MP00084** | Second argument is not a closed generic interface in a known family |
| **MP00085** | First argument missing or invalid |

See [error codes](./error-codes.md), [algorithm — container strategy](./mappa-generator-algorithm.md#7-container-strategy), and [PreferredInterfaceMapper.cs](../Mappa.Samples/PreferredInterfaceMapper.cs).

## MappaMapEnumMember, MappaMapEnumIgnore, and MappaMapEnumDefault

`[MappaMapEnumMember]`, `[MappaMapEnumIgnore]`, and `[MappaMapEnumDefault]` are applied to mapping methods. All three allow multiple instances and are **bidirectional**: the same declaration configures mapping in both directions (for example `TEnum` → `int` and `int` → `TEnum`).

Use them on **root enum map methods** (where the source or return type is an enum) and on **class/struct map methods** to configure nested enum properties being mapped.

### MappaMapEnumMember

`[MappaMapEnumMember]` declares an explicit pairing that overrides settings-based matching for that member:

- `[MappaMapEnumMember<TEnum>(TEnum, int)]` — pairs an enum member with an integral value;
- `[MappaMapEnumMember<TEnum>(TEnum, string)]` — pairs an enum member with a string value;
- `[MappaMapEnumMember<TEnum, TOtherEnum>(TEnum, TOtherEnum)]` — pairs members of two enums.

### MappaMapEnumIgnore

`[MappaMapEnumIgnore<TEnum>(TEnum)]` excludes a specific enum member from mapping. When that member is encountered at runtime, the fallback configured by `[MappaMapEnumDefault]` is applied (throw by default).

### MappaMapEnumDefault

`[MappaMapEnumDefault<TEnum>]` configures fallback behaviour when a value of `TEnum` cannot be mapped (for example because it was ignored or has no pairing):

- `Throw` (default) — throws `ArgumentOutOfRangeException`;
- `UseDefaultValue` — returns a default value supplied via a constructor overload: `TEnum` when the target is an enum, `int` when the target is integral, or `string` when the target is `string`.

### Multiplicity

- On a mapping method whose source or return type is itself an enum, at most **one** `[MappaMapEnumDefault]` may be present.
- On class/struct map methods, at most **one** `[MappaMapEnumDefault]` per distinct `TEnum` type may be present (for example one default for a nested `ConfigStatus` property and another for a nested `ConfigPriority` property).

### Settings interaction

`EnumStringMapSetting`, `EnumToEnumMapSetting`, and `CaseInsensitiveEnumMap` from `[MappaSettings]` still apply for members that are not overridden by these attributes.

### Diagnostics

| Code | Summary |
|------|---------|
| **MP00047** | An attribute references an enum that is not part of the current mapping. |
| **MP00048** | Conflicting `[MappaMapEnumMember]` declarations for the same enum. |
| **MP00049** | `[MappaMapEnumIgnore]` excludes a member also configured by `[MappaMapEnumMember]`. |
| **MP00050** | `[MappaMapEnumDefault]` uses `UseDefaultValue` without a default value. |
| **MP00051** | `[MappaMapEnumDefault]` default value is incompatible with the mapping target type. |
| **MP00052** | `[MappaMapEnumDefault]` provides a default value with behaviour `Throw` that will not be used. |
| **MP00053** | More than one `[MappaMapEnumDefault]` on a method that maps an enum directly. |
| **MP00054** | Multiple `[MappaMapEnumDefault]` attributes target the same enum on a class/struct map method. |

See also: [tutorial](./tutorial.md#enum-mapping-configuration-attributes), [algorithm](./mappa-generator-algorithm.md#4-enum-strategy), and [EnumMappingConfigurationMappers.cs](../Mappa.Samples/EnumMappingConfigurationMappers.cs).
